1. Vue d'ensemble de l'architecture

Principe de séparation des responsabilités

Doctrine fondamentale

MOTO Editor repose sur une séparation stricte entre trois couches :

  • MOTO Editor : édite, affiche, ouvre, sauvegarde, lance des commandes (jamais d'analyse profonde du code).
  • MOTO AI : assiste l'utilisateur, prédit, propose, route les demandes (jamais d'auto-application).
  • XENO-SSS∞ : opérations structurées sur projet complet (analyse architecturale, génération, validation).

Interfaces publiques clés

MotoAiKernel

Point d'entrée unique pour toutes les requêtes IA. Route les intentions vers le moteur approprié avec fallback sur les providers locaux (Ollama) ou distants (si configurés).

public class MotoAiKernel { public async Task<AiResponse> RouteIntentAsync(IntentRequest request); public void RegisterProvider(IAiProvider provider, int priority); public AiResponse GetFallback(IntentRequest request); }

CortexEngine

Maintient la mémoire cognitive de l'utilisateur : préférences de style, patterns récurrents, habitudes de navigation. Persiste dans .moto/cortex/memory.json.

public class CortexEngine { public void LearnFromAction(UserAction action); public StyleProfile GetCurrentStyle(); public IEnumerable<Suggestion> GetContextualSuggestions(DocumentContext ctx); }

4. Système de paramètres (data-driven)

Architecture du catalogue

SettingsCatalog (classe partial)

Regroupe ~300 paramètres en 15 catégories. Chaque paramètre est défini de manière déclarative avec type, valeur par défaut, contrainte et catégorie.

public partial class SettingsCatalog { // Apparence public static readonly SettingDefinition<bool> ShowMinimap = new("editor.minimap.enabled", true); public static readonly SettingDefinition<int> FontSize = new("editor.fontSize", 14, min:8, max:24); public static readonly SettingDefinition<string> Theme = new("appearance.theme", "Moto Dark"); // Éditeur public static readonly SettingDefinition<bool> WordWrap = new("editor.wordWrap", false); public static readonly SettingDefinition<int> TabSize = new("editor.tabSize", 4, min:1, max:8); // IA public static readonly SettingDefinition<bool> AiSuggestions = new("ai.suggestions.enabled", true); public static readonly SettingDefinition<string> AiProvider = new("ai.provider", "ollama"); }

Types de paramètres supportés

Persistance et application

SettingsEngine.Shared

Singleton gérant la persistance dans %AppData%/MotoEditor/settings.json. Charge au démarrage, sauvegarde à chaque modification.

public class SettingsEngine { public static readonly SettingsEngine Shared = new(); public T Get<T>(SettingDefinition<T> definition); public void Set<T>(SettingDefinition<T> definition, T value); public void Save(); public void Load(); }

SettingsApplier

Applique les paramètres en temps réel : thème, police, minimap, indentation, etc. Écoute les changements via INotifyPropertyChanged.

5. Agents intégrés (AgentIntegrated/)

Pipeline XENO

Architecture des agents

Les agents spécialisés sont orchestrés par XenoPipeline et exécutent des tâches structurées sur le projet complet. Chaque agent a un rôle précis et retourne un AgentResult.

public class XenoPipeline { public async Task<AgentResult> ExecuteAsync(AgentContext context); public void RegisterAgent(IAgent agent, int priority); } public interface IAgent { string Name { get; } Task<AgentResult> RunAsync(AgentContext context); bool CanHandle(AgentContext context); }

5. Agents intégrés (suite)

Contexte et résultats

AgentContext

Objet passé à chaque agent contenant le contexte d'exécution : projet actif, fichiers concernés, requête utilisateur, historique.

public class AgentContext { public Project ActiveProject { get; } public IEnumerable<string> TargetFiles { get; } public string UserQuery { get; } public IDictionary<string, object> Metadata { get; } public T GetMetadata<T>(string key, T defaultValue = default); public void SetMetadata<T>(string key, T value); }

AgentResult

Résultat retourné par un agent. Peut contenir des fichiers modifiés, des suggestions, des erreurs, ou un état de succès/échec.

public class AgentResult { public bool Success { get; } public string Message { get; } public IEnumerable<FileChange> Changes { get; } public IEnumerable<Suggestion> Suggestions { get; } public IEnumerable<Diagnostic> Diagnostics { get; } public static AgentResult Succeeded(string message = null); public static AgentResult Failed(string error); public static AgentResult WithChanges(IEnumerable<FileChange> changes); }

Registre des agents

AgentRegistry

Registre central permettant d'enregistrer, découvrir et invoquer les agents. Supporte les priorités et le filtrage par contexte.

public class AgentRegistry { public void Register(IAgent agent, int priority = 0); public IEnumerable<IAgent> GetAgentsFor(AgentContext context); public IAgent GetByName(string name); }

6. Flux de délégation Editor → AI → XENO

Principe de délégation

Analogie avec les éditeurs existants

MOTO Editor délègue les opérations complexes à XENO-SSS∞ de la même manière que :

  • VS Code appelle Copilot
  • Cursor appelle son backend IA
  • Zed appelle Claude Code

Mais en local, sans cloud. XENO est l'orchestrateur structuré qui exécute les opérations sur le projet complet.

Flux typique : génération de projet

// 1. Utilisateur demande "Créer un projet MAUI avec MVVM" Editor.UserAction("CreateProject", new { Template = "maui-mvvm" }); // 2. Editor route vers AI var intent = await MotoAiKernel.RouteIntentAsync(new IntentRequest { Type = IntentType.ProjectGeneration, Query = "Créer un projet MAUI avec MVVM", Context = CurrentWorkspace }); // 3. AI délègue à XENO if (intent.RequiresStructuredOperation) { var xenoResult = await XenoBridge.ExecuteAsync(new XenoRequest { Operation = XenoOperation.CreateProject, Parameters = intent.Parameters, Agents = ["AgentScanner", "AgentSynthesizer", "AgentConnector", "AgentValidator"] }); // 4. Editor applique les changements if (xenoResult.Success) { await FileTreeService.RefreshAsync(); await BuildEngine.BuildAsync(xenoResult.GeneratedFiles); } }

Flux typique : suggestion contextuelle

// 1. Utilisateur tape du code Editor.OnTextChanged(document, position); // 2. CortexEngine apprend de l'action CortexEngine.LearnFromAction(new UserAction { Type = ActionType.CodeEdit, Document = document, Position = position, Timestamp = DateTime.Now }); // 3. ContextEngine propose des suggestions var suggestions = await ContextEngine.GetSuggestionsAsync(new DocumentContext { Document = document, CursorPosition = position, RecentActions = CortexEngine.GetRecentActions(10) }); // 4. UI affiche les suggestions (ghost text, panneau) Editor.ShowSuggestions(suggestions);

Conventions de code

Asynchronicité

Toutes les méthodes effectuant des opérations I/O ou IA sont asynchrones et retournent Task<T>.

Injection de dépendances

Les services sont injectés via le conteneur MAUI. Les moteurs sont des singletons accessibles via des propriétés statiques (ex: SettingsEngine.Shared).

Gestion des erreurs

Les erreurs sont capturées et exposées via des Diagnostic ou des AgentResult.Failed. L'UI affiche les erreurs dans les badges d'onglets et le panneau de diagnostics.
