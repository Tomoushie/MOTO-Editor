1. Vision, doctrine & état des lieux

Vision : reproduire les capacités de Zed (3 docks, terminal, IA intégrée, collab) en 100 % fait maison, avec une interface minimaliste type Claude Code / ChatGPT et une complexité portée par le backend et 100+ paramètres data-driven.

Doctrine : backend d'abord, UI mince · pas d'UI factice · MOTO Editor édite/affiche, MOTO AI assiste/route, XENO-SSS∞ structure · délégation comme « Zed → Claude Code ».

2. Horizon 1 — Stabilisation & finitions SEPT. – OCT. 2026

Objectif : zéro défaut visible et base saine avant tout nouveau chantier. Chaque lot passe par revue croisée + rebuild Debug/Release avant commit.

A1 · Chantier barre de titre bleue (session dédiée) PRIORITÉ 1

  • Sondes : lecture GWL_STYLE (bits WS_CAPTION), Live Visual Tree, teinte de rangée
  • Interdit : retenter SetBorderAndTitleBar (3 échecs, fenêtre invisible)
  • Interdit : migration MAUI/.NET (échec .NET 10 du 30/08, WASDK 1.8 épinglé)
  • Livrable : une seule titlebar, drag custom, boutons –/▢/✕, packagé + non-packagé

A2 · Persistance & réglages

  • Persistance de disposition : docks (hauteur, visibilité, côté des panneaux)
  • Settings 100+ exposés : terminal.*, docks.*, ghost text, décodage spéculatif
  • Templates de réglages + recherche (déjà partiel) consolidés

A3 · Qualité & dette

  • Warnings ~300 → objectif < 50 (CS8618/CS8625/CS0618 priorisés)
  • Squelettes de tests xUnit via agent.tests.micro sur Moto.Core
  • Nettoyage code mort (Moto.UI/ non raccordé, doublons CustomMenuBarView)
  • Crash-log + breadcrumbs conservés (observabilité titlebar)

Jalon M1 (fin oct. 2026)

Application sans défaut visuel bloquant, disposition persistante, 100+ paramètres exposés, build < 50 warnings. → Go/No-Go Horizon 2.

4. Horizon 3 — Plateforme, distribution & croissance JANV. – JUIN 2027

D1 · Sortir de Windows

  • PlatformEngine : portage macOS/Linux (générateurs Avalonia + CI)
  • Validation incrémentale par plateforme ; feature-parity progressive
  • Accessibilité complète (UI Automation / WCAG) documentée et testée
  • i18n FR/EN (LanguagePack extensible)

D2 · Distribution & modèle économique

  • Installateur per-user single-file (sans UAC) + MSIX + winget
  • Mises à jour signées Ed25519 (AtomicUpdater) en canal stable/bêta
  • Open source (licence à trancher : MIT vs GPL) + freemium Pro 10–20 $/mois
  • GitHub Releases automatisées + notes de version via ChangelogAgent

  • Collab temps réel : CRDT réel + présence (CollabSession/PatchEngine)

  • Onboarding : PedagogyEngine, Story Mode, missions guidées

Jalon M3 (juin 2027)

v1.0 publique : Windows + au moins une plateforme secondaire, CRDT collab, DAP, i18n, accessibilité, modèle freemium lancé. Objectif marché : trajectoire 5–10 % à 5 ans.

Conclusion

Cette feuille de route traduit la doctrine en plan d'exécution : stabiliser d'abord (Horizon 1), brancher le cerveau (Horizon 2 : MotoBridge/XENO), puis ouvrir la plateforme (Horizon 3). Elle assume deux renoncements tactiques — pas de migration .NET/MAUI sous pression, pas d'attaque frontale de VS Code — au profit d'une stratégie de niche : IDE minimaliste, puissant & accessible.

Le rythme est volontairement jalonné (M1/M2/M3) avec Go/No-Go : chaque horizon ne démarre que si le précédent est démontré stable. C'est la condition pour qu'une équipe unique livre un produit vendable sans sacrifier la qualité.
