1. Synthèse exécutive

MOTO Editor est un environnement de développement entièrement local qui reproduit les capacités d'un IDE moderne de type Zed — docks modulaires, terminal, IA intégrée, collaboration — avec une interface minimaliste inspirée de Claude Code/ChatGPT et une complexité déplacée vers le backend et vers plus de 100 paramètres de configuration. Le projet est développé « fait maison » : aucun framework UI tiers, aucun service cloud, aucune télémétrie.

Ce que le projet est (et n'est pas)

✅ C'est

  • Un éditeur/IDE local-first : édite, affiche, ouvre, sauvegarde, exécute des commandes.
  • Un shell modulaire (3 docks) avec terminal interactif réel et glisser-déposer.
  • Une IA locale (Ollama/ONNX) assistée d'un pipeline structuré XENO-SSS∞.
  • Un chantier transparent : bugs publics, roadmap ouverte, méthode documentée.

⚠️ Ce n'est (volontairement) pas

  • Pas un produit cloud : aucune donnée ne quitte la machine.
  • Pas un clone de code : inspiration Zed/VS Code, réécriture C# intégrale (Zed = GPL).
  • Pas encore multiplateforme : Windows d'abord, portages planifiés (PlatformEngine).
  • Pas une v1.0 : LSP Roslyn, CRDT réel, DAP, tests, i18n, accessibilité = « à venir ».

2. Genèse & méthode « 1 humain + 3 IA »

Le projet est né d'un constat simple : les IDE modernes sont lourds, cloud-dépendants ou verrouillés. Le fondateur, sans formation de développeur, a choisi une méthode inhabituelle : orchestrer trois IA complémentaires pour construire un vrai produit, en assumant publiquement ce fonctionnement (build in public).

3. Doctrine & vision produit

Interface minimaliste

  • Surface type Claude Code/ChatGPT : une saisie, des chips, zéro surcharge.
  • Divulgation progressive : la richesse se déverrouille dans les Réglages.

Complexité backend

  • Moteurs, services, agents dans Moto.Core / Snake2000.Engine.
  • 100+ paramètres data-driven (1 ligne = 1 paramètre).

Fait maison

  • Inspiration Zed, réécriture C# intégrale (zéro copie, Zed = GPL).
  • Pas de dépendance runtime externe ; pas d'UI factice.

Séparation stricte des responsabilités

Modèle d'appel : MOTO Editor appelle XENO comme Zed appelle Claude Code — l'éditeur propose et affiche, l'utilisateur (ou XENO) applique. Règle d'architecture vérifiée dans le code : « MOTO propose, l'utilisateur/XENO applique » (ex. InlineDiffPreviewService ne modifie jamais le document).

Contraintes techniques assumées (objectivité)

Connues & documentées

  • Sous-système titlebar WinUI3/MAUI instable (barre bleue : 3 échecs SetBorderAndTitleBar).
  • ~300 warnings de build (CS8618/CS8625/CS0618) — dette en cours de résorption.
  • Windows uniquement aujourd'hui ; macOS/Linux = PlatformEngine (planifié).

Choix de prudence

  • Pas de migration .NET/MAUI sous pression (échec .NET 10 du 30/08 sur ce projet).
  • Fichiers > 400 lignes jamais régénérés d'un bloc (risque de corruption silencieuse).
  • Chantiers isolés + revue croisée avant commit.

6. L'éditeur : cœur de métier

Shell 4 colonnes

  • Explorateur de fichiers redimensionnable (DataTemplate 4 colonnes : indent, chevron, glyphe, nom).
  • Onglets + badges d'état ; recherche par nom de fichier en direct.
  • StatusBar : état, erreurs, monitoring, dashboard performance (item 107).
  • Palette de commandes Ctrl+Shift+P (ranking maison).

CodeEditorView (WebView maison)

  • Gutter + numéros de ligne ; coloration syntaxique incrémentale.
  • Mini-map compressée ; scroll horizontal.
  • Ghost text (Tab) issu de l'IA locale.
  • Undo 1000 niveaux via PieceTableBuffer (Tier 30).

16. SWOT & positionnement

Forces

  • 100 % local, léger, sans Electron ; sécurité signée Ed25519.
  • Architecture modulaire Zed livrée (5 briques) + terminal réel.
  • ~300 paramètres data-driven ; IA locale + 20 agents.
  • Méthode transparente (revues croisées, mémoire QWEN/CLAUDE.md).

Faiblesses

  • Notoriété nulle ; équipe d'une personne ; Windows uniquement.
  • ~300 warnings ; barre bleue non résolue ; LSP/CRDT/DAP absents.
  • Dépendance à la stack MAUI/WinUI3 (régressions possibles).

Opportunités

  • Marché +10,8 %/an ; 84 % de devs vers l'IA ; fatigue VS Code.
  • Niches privacy & accessibilité sous-servies ; modèle freemium prouvé.
  • Histoire « 1 humain + 3 IA » = actif marketing organique.

Menaces

  • VS Code 75,9 % ; entrants financés (Cursor, Windsurf) ; Zed rapide.
  • Adoption entreprise lente ; fragmentation des alternatives.

Positionnement retenu

Ne pas attaquer VS Code frontalement. Créer et dominer la catégorie « IDE minimaliste, local & accessible » : façade simple type Claude Code, profondeur Zed, confidentialité totale. Objectif prudent : 5-10 % de part de marché à 5 ans (trajectoire Zed comme référence).

Pourquoi cette transparence est un actif

Chaque limite ci-dessus est publique (roadmap, tickets, devlog). Dans un marché où la confiance est le premier critère d'adoption d'un outil de code, « dire vrai, dire mesuré, dire utile » (charte éditoriale) remplace le budget marketing : les échecs documentés (barre bleue, échec .NET 10 du 30/08) sont publiés tels quels.

Conclusion

MOTO Editor est, à ce jour, un IDE local-first fonctionnel et cohérent : shell modulaire façon Zed complet, terminal réel, IA locale orchestrée, sécurité de niveau professionnel, et un système de réglages qui porte la complexité promise (100+ paramètres). Il n'est ni plus rapide que Zed, ni plus riche que VS Code — et ne cherche pas à l'être : il vise la niche minimalisme + local + accessibilité, avec une méthode de développement (1 humain + 3 IA, revues croisées, mémoire persistante) qui compense l'absence d'équipe. Le passage en bêta publique est conditionné à l'atteinte du niveau visuel « élevé » et à la v1.0 fonctionnelle (LSP, CRDT réel, DAP, tests, i18n, accessibilité).
